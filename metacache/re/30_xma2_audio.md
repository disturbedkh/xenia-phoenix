# XMA2 audio

## Core facts

- **XMA2** = Xbox Media Audio 2, lossy compressed audio codec used by virtually every 360 title for music, SFX, and (often) voice.
- Closely related to **WMA Pro** (Windows Media Audio Professional) — XMA2 is a constrained / repackaged WMA Pro.
- Hardware-accelerated on a dedicated DSP block in the 360 audio I/O.
- Variable bitrate, multi-channel (mono / stereo / 5.1), 32-256 kbps typical.

## Xenia handling

`src/xenia/apu/`:

- `xma_decoder.cc` — top-level decoder, schedules contexts.
- `xma_context_new.cc` — default production decoder (`--xma_decoder=new`).
- `xma_register_file.h` — guest-visible register file (matches hardware MMIO layout).

## Packet layout (2048 bytes, Phase 1.4)

Each **packet** is exactly **2048 bytes** on the wire. The first **4 bytes** are the packet header; the remaining **2044 bytes** are frame bitstream data.

| Offset | Field | Notes |
|--------|--------|--------|
| 0 | `frame_count << 2 \| frame_offset_hi` | Top 6 bits: number of frames that **begin** in this packet (XMA2 only). Low 2 bits: high part of first-frame bit offset. |
| 1 | `frame_offset_mid` | Middle bits of first-frame offset (bits). |
| 2 | `frame_offset_lo \| metadata` | Low 5 bits of offset; low 3 bits = packet metadata (`1` = XMA2). |
| 3 | `skip_count` | `0xFF` = full packet skip (no new frames). Otherwise skip `skip_count + 1` packets before the next decodable packet. |
| 4–2047 | Frame bitstream | Parsed with 15-bit frame headers (`kBitsPerFrameHeader = 15`). |

**First frame bit offset** (from `xma_helpers.h`):

```text
val = ((packet[0] & 3) << 13) | (packet[1] << 5) | (packet[2] >> 3)
first_frame_bits = val + 32   // always at least 32 bits past packet start
```

FFmpeg parser (`third_party/FFmpeg/libavcodec/xma_parser.c`) uses `duration += packet[0] * 128` and `skip_packets = packet[3] + 1` per 2048-byte block.

## Guest context (`XMA_CONTEXT_DATA`, 64 bytes)

See `src/xenia/apu/xma_context.h`. Key fields for smoke / harness:

- `input_buffer_0/1_ptr` — **physical** addresses of 2048-byte-aligned packet blocks.
- `input_buffer_read_offset` — bit offset into the current buffer (games may briefly use `0`; decoder clamps to `kBitsPerPacketHeader`).
- `sample_rate` — enum 0..3 → 24 / 32 / 44.1 / 48 kHz.
- `is_stereo`, `subframe_decode_count`, loop fields (`loop_start`, `loop_end`, `loop_subframe_*`).

Output PCM is **big-endian int16**, 512 samples per frame per channel, written in **256-byte subframe blocks** to a guest ring buffer.

## Bug surface

- **Choppy playback** — context scheduling / under-decode.
- **Pitch shift** — sample-rate metadata misread.
- **Channel swap** — multi-channel layout mismatch.
- **Click/pop on loop** — loop boundary handling.
- **Whole-track silence** — packet header parse fail, decoder wedged.
