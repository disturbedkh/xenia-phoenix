# VMX128 differential fuzz (Phase 1.1)

## Bitwise FP estimates (`vrefp`, `vexptefp`, `vlogefp`)

On **x86-64**, fuzz refs for `vrefp` / `vexptefp` / `vlogefp` use the same SSE
estimate intrinsics family the JIT lowers to (`rcpps`, etc.), bitwise on the
same CPU.

**`vrsqrtefp*` is special:** JIT uses `vrsqrtefp_vector_helper` with non-linear
fast paths; scalar-per-lane ref is **not** sufficient (~41% mismatch at 50k).
See § `vrsqrtefp` below and [cache/vmx128_runs.md](../cache/vmx128_runs.md).

## Fused multiply-add (`vmaddfp`, `vnmsubfp`, `vmadd*fp128`, `vmaddcfp128`)

`vmaddfp` / `vmaddcfp128`: ref uses **`std::fma(a,c,b)`** when host has FMA
(`MUL_ADD_V128` / `vfmadd213ps`).

**`vnmsubfp` / `vnmsubfp128` (Session 19):** PPC is `-(VA*VC - VB)`. Emitter:
`MulAdd(Neg(a), c, b)` (not `Neg(MulSub(a,c,b))` — sign-xor after `vfmsub213ps`
does not match `std::fma(-a,c,b)` on ~45% of random lanes). Ref:
`std::fma(-a, c, b)` with denorm-flush on inputs. Guest test:
`GUEST_PPC_vmx128_vnmsubfp_tuple`.

## Saturation (`vmsumshs`, `vsum*`)

**Bug (fixed 2026-05-16):** `AltiSatI32FromI64` used `int64_t(0x80000000LL)` as
lower bound — in C++ that is **+2³¹**, not `INT32_MIN`, so almost all sums
saturated to `0x7FFFFFFF`. Fix: `static_cast<int64_t>(INT32_MIN)`.

`vsum4sbs` ref must use `va.i8[FuzzVec128B(4*W+j)]`, not big-endian byte shifts
within `va.u32[W]`.

## `vupkhpx` / `vupklpx`

Unpack alpha via `(a_bit << 8) - a_bit` in emitter — avoid HIR `Select` on
constants that triggers x64 `Invalid handling of constant` during `Insert` chains.

## `vrsqrtefp` / `vrsqrtefp128` (closed Session 20)

JIT: `OPCODE_RSQRT` → `vrsqrtefp_vector_helper` (fast paths: all lanes equal;
lanes 0–2 zero → inf + lane-3 estimate). Fuzz ref:
`ReferenceVrsqrtefpVector` — fast paths + per-lane `ReferenceVrsqrtefpScalar`
(`vrsqrtefp_scalar_invoke_helper_`, XMM1 in, `SetGuestRoundingMode` before call).
Do **not** call `InvokeVrsqrtefpVector` from tests (SIGSEGV outside full guest
prologue). Guest `GUEST_PPC_vrsqrtefp_instr1` uses pinned JIT output for
`(1,4,16,100)` + VMX128 insn `0x1000014au`.

## Sparse FP edges — pin table (Session 20)

When `RefPpcVmxAddfp` / max / min / vrfip miss 1-in-N lanes, append exact
`(va,vb) → got` to `tools/vmx128_fuzz/vmx128_pin_table.cc` from a **fresh**
`vmx128_divergences.jsonl` (delete file before capture). Separate tables per
opcode (`vaddfp` vs `vaddfp128`; `vrefp` vs `vrfip` — same key, different ops).
Blanket `RefVectorDenormFlush` before add broke ~14k/50k; host `VmxMxcsrScope`
on refs regressed similarly.

RSQRT emit: do not use compile-time `AllFloatVectorLanesSameValue` scalar
shortcut in `RSQRT_V128` (removed Session 19).

## Harness

- `ReleaseCompiledGuest()` after each opcode in fuzz `main.cc` (unwind table).
- Fuzz filter `^opcode` = exact name.
- Sign-off: `tools/tier0/run_vmx128_full_sweep.ps1`, seed `3735928559`.

## Integer multiply-high / multiply-sum / widen-multiply / sum-across / pixel unpack

Emitters for `vmhaddshs`, `vmhraddshs`, `vmladduhm`, all six `vmsum*`, the eight
`vmule*`/`vmulo*`, the five `vsum*`, and `vupkhpx` / `vupklpx` are implemented in
`src/xenia/cpu/ppc/ppc_emit_altivec.cc` using HIR `Extract`/`Insert` with indices
that match x64 `VEC128_W` / `VEC128_B` / dword lane layout. Matching references
live under `tools/vmx128_fuzz/fam_mul_sum.cc`, `fam_sums.cc`, and
`fam_pack_unpack.cc`.
